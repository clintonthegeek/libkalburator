## What shipped (tag `v0.67`)

1. **`CollectionInfo.contentTypes` populated** (`1a48258`, merge `3474c30`) — exactly the
   RFC's §2: `CalDavProvider::onDiscoveryFinished` and
   `MultiProtocolDavProvider::onCalDavFinished` copy `supportsVEvent`/`supportsVTodo` into
   the rows as `"VEVENT"`/`"VTODO"`; the §2 optional symmetry is included —
   `CardDavCapabilityDiscovery` rows carry `"VCARD"` (so both CardDavProvider and the
   multiproto CardDAV leg get it). `ci.type` untouched, `contentTypesFromCaps()`/backend
   priming untouched (§2.1). Regression tests per §2.2: events-only / tasks-only / mixed
   calendars asserted through CalDavProvider, MultiProtocolDavProvider, and CardDavProvider
   (`FakeCalDavServer` gained `setCalendarComponents()`).
2. **`ProviderManager::addProvider` registers backends for pre-connected providers**
   (`9584f2f`, merge `f170139`) — the PlanStan fix, committed per the v0.61 precedent
   (authored PlanStan-side while debugging the accounts-first wizard e2e; landed on
   `fix/preconnected-provider-registration` off `main`). Pinned by
   `addProvider_registersBackendsForPreConnectedProvider`.
3. **§4.4 dialog test realigned** (`d1e924b`) — the pre-existing
   `tst_providerconfigdialog::failedTestConnection_surfacesErrorMessage` failure both
   consumer teams independently confirmed on clean v0.66 was a pre-§4.4 test asserting the
   raw error lands in the status label; §4.4 moved it to the Details disclosure. The test
   now pins the actual contract. `main` is 137/137 for the first time since the polish.
4. **calendarsOnly ctor-argument swallow fixed** (`fac8522`, merge `b47d75e`; found by the
   2026-06-10 audit) — both contributions passed `parent` into `(bool calendarsOnly,
   QObject *parent)` ctors, so the pointer bound to the bool and the parent was dropped;
   the provider-side mode never engaged. Fixed **behavior-preserving** (`(false, parent)`):
   registry-created providers keep the full surface — WildPalms contacts conduits are
   unaffected. Per-account mode selection is an open design question (audit follow-up
   WP-A1) and will come to both consumers as an RFC.
